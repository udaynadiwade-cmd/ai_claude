Business model canvas · live landed-cost platform · August 2026

The price nobody publishes

Befach has API access to Alibaba, 1688, Amazon and a dozen other marketplaces, plus exchange-rate and historical-price feeds, plus two years and roughly 100–150 real shipments of import execution. The proposal: instant landed price for any product, in rupees. Here is the canvas — and the two corrections it needs first.

Correction one — landed-cost calculators already exist in India

The premise as stated is wrong

The claim was "there is no website as such in India that provides a landed price for importers." A single search returns at least nine live Indian landed-cost/import-duty calculators: EximPe, Patron Accounting, Karbon Card, Toolvala, Eximigo, ONS Logistics, DutyDecoder, Mundhra Consulting, CalcWise. Fact DutyDecoder already advertises AI-powered HS-code classification. This is a populated space, not an empty one.

This is the fourth time in this research series a market assumed empty turned out crowded on checking — after bearings (Ranigunj), electricals (Begum Bazaar) and water (Romegamart). The pattern is worth naming, not just the individual finding.

What is genuinely different, and it is real

Every existing calculator is manual-input: the user types a product value and an HS code, and it returns duty. They compute tax on a number you already have. None of them are connected to live product catalogues.

Befach's version would be search-driven: find the actual product on 1688 or Alibaba, pull its actual current price, apply live FX, apply duty, add real freight — and return a delivered rupee price for a specific listing, not an abstract calculation. No competitor found doing this — that is the defensible gap, and it is narrower and sharper than "no landed-cost tool exists."

Correction two — a free calculator is not a revenue model

Look at what the existing nine actually are

EximPe is a payments company. ONS Logistics is a logistics company. Karbon Card is a fintech. Patron and Mundhra are accounting/consulting firms. Every one of them gives the calculator away free — it is a lead magnet for the business behind it, never the business itself.

That is the correct way to read this proposal too. The instant-quote tool is Befach's customer-acquisition channel; the revenue is the shipment it converts into. This is not a downgrade of the idea — it is what makes it viable, because Befach already owns the thing the tool feeds: import execution, customs, freight, roughly 100–150 shipments of real practice. The calculator without the fulfilment behind it would be another free tool. The fulfilment without the calculator is what Befach already does, slowly and manually.

The Business Model Canvas

Key Partnerships

  • API providers — the aggregator supplying Alibaba, 1688, Amazon, Shopee, Lazada and the rest
  • Freight forwarders and customs house agents
  • Chinese suppliers and on-ground sourcing/QC agents
  • FX and cross-border payment providers
  • Testing/certification labs for BIS and QCO-controlled goods

Key Activities

  • HS-code classification and duty mapping — the hard, unglamorous core; one wrong quote costs the relationship
  • API integration and data-freshness management
  • Freight-rate modelling by lane, weight and volume
  • Import execution: customs clearance, QC, delivery
  • Supplier verification on listings surfaced

Value Propositions

  • A delivered rupee price for a real, specific listing — not a calculator you feed numbers into
  • Minutes instead of days: replaces the manual back-and-forth every sourcing agent runs today
  • Removes the single biggest unknown for a first-time importer — what this actually costs landed
  • Then executes the import, so the quote is not just information
  • Compliance visibility: flag BIS/QCO-restricted goods before the buyer commits

Customer Relationships

  • Self-serve for the quote — no salesperson needed to get a price
  • High-touch for the shipment itself, which is where Befach's experience shows
  • Repeat by design: an importer who lands one order well comes back for the next
  • Saved quotes and price-history alerts as the reason to return

Customer Segments

  • The existing ~100 B2B import clients — warm, already transacted
  • SME importers and first-time importers who do not know what landing costs
  • Amazon/Flipkart/Meesho sellers sourcing new products
  • D2C brands exploring private label
  • Small manufacturers importing components and raw material

Key Resources

  • The API access itself — Alibaba, 1688, Amazon, plus FX and historical-price feeds
  • 100–150 shipments of real import execution — customs, freight, documentation, learned the expensive way
  • The duty/HS-code logic once built and validated
  • The existing client list
  • Accumulated quote data — what people ask for reveals demand nobody else can see

Channels

  • The free quote tool itself — the acquisition engine, not the product
  • Search: "landed cost of [product] from China" is a real, high-intent query with commercial buyers behind it
  • The existing ~100 clients, contacted directly
  • WhatsApp — where Indian SME buyers actually transact
  • Seller communities on Amazon/Flipkart/Meesho

Revenue Streams

  • Margin on the executed import — the primary and, at first, only real line
  • Freight and logistics margin
  • Sourcing/QC service fee on managed orders
  • Later, if usage justifies it: subscription for price history, alerts and bulk quoting
  • Not the quote itself — charging for it kills the acquisition engine

Cost Structure

  • API subscription fees — recurring, and a structural dependency (see risk below)
  • Engineering: build and continuous maintenance as source sites change
  • Customs and compliance expertise — the duty logic must stay current with every tariff revision
  • Working capital per shipment
  • Customer acquisition beyond the organic search channel

The three risks that decide whether this works

RiskWhy it mattersWhat reduces it
API dependency The Key Resource at the centre of this model is rented. If the provider raises prices, changes terms, or loses upstream access, the product stops working. Alibaba and Amazon can also restrict third-party data access at will. Treat the API as a wedge, not a moat. The durable asset is the duty logic, the client relationships and the accumulated quote data — all of which survive an API change.
Quote accuracy A landed price is a promise. Wrong HS code, missed cess, or unmodelled freight and the customer pays more than quoted — once. Trust in this product is binary. Quote conservatively with a stated range at first; narrow it as real shipment data accumulates. Befach's own 100–150 shipments are the initial calibration set.
Conversion, not traffic A free tool can attract thousands of browsers who never import anything. Traffic without conversion is a cost centre. Measure quote-to-shipment conversion from week one, not visits. If it does not convert, the tool is marketing spend, not a business.

Go-to-market — the first move, specifically

  1. Do not build the platform first. Take the existing ~100 import clients and offer instant quoting manually, using the APIs internally. No public site, no product build.
  2. Measure one number: of the quotes given, how many convert to shipments. That single ratio decides whether this is a business or a free tool.
  3. Only if it converts, build the public search-and-quote page and let organic search bring in first-time importers.
  4. Category focus still applies. Start quoting in one or two categories where Befach already knows the duty structure and compliance regime cold — not across all 36 Alibaba categories, which is the compliance trap this series has already documented once.
